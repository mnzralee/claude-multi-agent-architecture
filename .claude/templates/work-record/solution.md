## Guidelines

### Approach Description
- Keep high-level and accessible
- Explain the strategy, not every detail
- Use diagrams for complex architectures

### Alternatives Considered
- Document even if obvious
- Helps future readers understand trade-offs
- Shows thoughtful decision-making

### Files Modified
- Complete list with brief descriptions
- Helps readers navigate changes
- Useful for code review

### Code Highlights
- Only include significant/interesting code
- Add explanatory comments
- Show before/after for changes
